# rev B minimum-tier bring-up ROM

`revb_bringup.bin` (16 KiB, org 0x0000) is the **B1 minimum-tier** firmware:
CPU + Memory + I/O(UART) only, no video, no keyboard, no interrupts. It exists so
the minimum tier has something observable to run before ekta37 (which needs video)
can be booted at B2.

Generated by `build_bringup.py` (self-contained 8080 assembler — no toolchain).
Rebuild from the repository root:
`python3 spinoffs/minimal-vga/roms/revb-bringup/build_bringup.py`. The image is **8080-subset only**, so cosim
is its oracle.

Behavior (all output on the 8251 USART, port 0x08 data / 0x09 ctl-status):

```
VJUGA rev B bring-up
RAM PASS            (fixed A5/5A + low-address-byte tests over 0x4000..0xD6FF)
ROM OK              (whole-ROM checksum == 0 mod 256)
READY               (then the serial monitor)
```

Serial monitor (single-letter commands, hex args): `A`hhhh set address,
`D`ump 16 bytes, `W`hh deposit byte + advance, `G`o (jump to address). The
current guard compares startup TX bytes between the C oracle and the HDL twin.
It builds a fast variant testing `4000h..40FFh`, then checks the transmitted
banner and `RAM PASS` result. The twin stops after the expected TX count; it
does not inject `A`/`D`/`W`/`G` commands or qualify their interactive behavior.
The [physical bench record](../../docs/rev-b-b1-bench-log.md) remains a template.

The C oracle models 8251 status and data registers; TxRDY is not a retained
control-port write. The twin uses the modeled 8251 with a direct baud-clock
source because this historical bring-up ROM does not program D57. Byte-stream
agreement does not establish exact UART timing or the normal PIT-clocked
NETC10/DIAG path.

Verified by `spinoffs/minimal-vga/sim/revb_bringup_check.sh` (T1.2).
